Step 1 · Find & log

We gather the raw material

Funding calls are checked and sorted like traffic lights. After an event, someone logs what happened in two minutes or pastes a message.

Step 2 · Draft

Claude writes a first draft

Bid outlines, social posts and the newsletter, in TWEA's voice, using only facts we logged. Gaps show as [to fill in].

Step 3 · Approve

A person stamps it

Giulio and the comms team read, edit and stamp each draft: Approved, Send back or Not now. Nothing is posted, sent or submitted without that stamp.

        Automations

Two options for the meeting follow below.

        Option to discuss on 2 December · starter kit ready

        Run the automations from TWEA's own GitHub

        Needs Richard's go-ahead

        Today the four jobs above run from Giulio's Claude account. To make them TWEA's, so anyone who manages the project can run, change or hand them on, the same jobs can run as scheduled GitHub Actions in a TWEA-owned repository, using TWEA's own Claude API key.

        How it would work
        1. Every Monday and Thursday, and at quarter end, GitHub runs the job and Claude searches the web.
        2. The results arrive as a pull request: new funding, stories, bid and post drafts, or the newsletter.
        3. A TWEA reviewer reads it and merges it, which is the approval step. Nothing is published before that.
        4. This tool, hosted free on GitHub Pages, shows the merged results. The quarter reminder arrives as a GitHub issue.
        What it would need
        • Richard agreeing to it, and a GitHub account or organisation owned by TWEA
        • A Claude API key for TWEA, with a monthly spending limit (paid per use)
        • One or two people who can review and merge pull requests
        • About 30 minutes to set up by following the README

        The starter kit is built and ready to upload. It has not been run against the live Claude API yet. Its first run should be watched.

        Option to discuss on 2 December · not set up

        Automatic posting with Metricool

        Needs Richard's go-ahead

        Today, approved posts are copied into the social media tools by hand. Metricool is a social media scheduler with a built-in review step. With it, approved posts could go straight into a posting schedule, and a person would still give the final approval before anything is published.

        How it would work
        1. A post is drafted here and stamped Approved, as now.
        2. It's sent to TWEA's Metricool account as "waiting for review", with a suggested time.
        3. Richard or the comms team gets an email and approves or rejects it in Metricool. One rejection stops it.
        4. Only then is it published on LinkedIn, X or Instagram.
        What it would need
        • Richard agreeing to use it on TWEA's behalf
        • A TWEA Metricool account, set up and owned by TWEA, with its social accounts connected
        • The comms team added as reviewers
        • A Metricool plan that includes the review step

        TWEA's social accounts are not connected to anything here, and nothing will be until Richard asks for it.
